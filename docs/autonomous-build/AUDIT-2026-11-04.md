## 2. Defects found during the audit (all in this change)

1. **Queued work was never executed.** `runSchedulerOnce`/`claimDueJobs` leased jobs and returned
   them; nothing dispatched them. Both `/api/jobs/scheduler/run` and `/api/scheduler/run` advertised
   "run the scheduler" but only created the lease — a job then expired and eventually dead-lettered
   with `LEASE_EXPIRED`. Fixed by `src/engine.ts` (claim → dispatch → settle) and by making those
   endpoints execute a real engine tick.
2. **Approvals were a dead end.** A decided approval never released the job or orchestration task
   waiting on it.
3. **Audit foreign-key misuse.** `Job` helpers wrote `AuditEvent.runId = job.workflowRunId`, but
   `AuditEvent.runId` references `AgentRun`. Any such write failed with `P2003`
   (`AuditEvent_runId_fkey`) — latent because the paths were unreachable until (2) was fixed.
   The workflow run id now travels in the audit payload instead.

## 3. Prioritised roadmap

**P0 — autonomy that actually runs (delivered here)**
- `src/engine.ts`: claim → dispatch → settle, lease heartbeats during execution, at-least-once
  semantics, crash recovery, kill-switch and per-workspace isolation, audit trail
  (`engine_job_succeeded` / `engine_job_failed` / `engine_job_retry`).
- Background loop started by the server (`AUTOMATION_ENGINE=off` disables it).
- Approval decisions release or reject the blocked work.
- `GET /api/engine/status`, `POST /api/engine/tick` (OWNER/ADMIN), live panel in Agent Control.

**P1 — make the company produce real work**
- Provider-independent AI layer: per-agent model selection, provider fallback, structured
  (schema-validated) responses, token/cost accounting per run, rate-limit handling.
- Replace `departmentProduces()` stubs with agent actions that call that layer and persist outputs.
- Orchestration driver out of the request path (run as engine-dispatched work instead of a
  synchronous loop) so an orchestration survives a restart without an operator.

**P2 — clipping and publishing**
- Media pipeline: source ingest → transcript → highlight scoring → clip plan → subtitle burn-in →
  vertical render (ffmpeg), with artefacts stored per workspace.
- Publishing connectors behind the existing approval gate; every publish requires an approved
  approval row and is idempotent per (platform, account, clip).

**P3 — revenue truth**
- Affiliate attribution (click → conversion reconciliation), payout export, revenue per campaign /
  creator / clip.
- Analytics: replace stored snapshots with derived queries where possible.

**P4 — surface**
- Job/engine monitor, agent org chart, workflow builder, publishing approval centre in the dashboard,
  all bound to the APIs above (no placeholder analytics).

**P5 — delivery**
- Dockerfile + compose for a self-hosted Linux deployment, healthchecks, migration-on-boot,
  backup/restore notes; extend CI with an end-to-end smoke run.

## 4. Verification of this change

- `npm run typecheck`, `npm run build`, `npm run lint`: pass.
- `vitest run`: 31 files / 97 tests pass (87 before, +10 engine tests).
- Live run against a real server and PostgreSQL: a run created with no HTTP trigger was picked up
  by the background engine within one poll interval (3 s), both steps executed, job `SUCCEEDED` on
  attempt 1, audit event `engine_job_succeeded` written.
- Workspace scan is capped per tick (job rows are under forced row-level security, so a tick cannot
  pre-filter globally): the newest workspaces are always examined and the rest rotate.
- Not automatically verified: the signed-in dashboard panel (the SPA reloads the document on login,
  which ends an automated browser session; the endpoints behind it are covered by tests).
