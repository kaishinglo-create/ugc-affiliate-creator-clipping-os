# Acceptance Criteria

## Phase 1 — Baseline
- [x] Repository has clear standalone scope and run instructions.
- [x] Responsive dashboard has navigation for product areas.
- [x] Demo data and disconnected integrations are labeled honestly.
- [ ] npm run check passes on Node.js 18+.
- [ ] Automated smoke tests and CI exist.

## Phase 2 — App foundation
- [ ] Choose framework and document trade-offs.
- [ ] Add accessible loading, empty, error and success states.
- [ ] Validate all inputs server-side.
- [ ] Add persistent storage, migrations and backups.
- [ ] Add authentication, authorization and secure sessions.

## Phase 3 — Automation
- [ ] Durable workflow queue supports retries, cancellation and idempotency.
- [ ] Internal agent runtime has typed tools, task budgets and audit events.
- [ ] AI gateway supports verified providers, timeouts and validated structured output.
- [ ] No implicit paid-provider fallback.
- [ ] Approval gates protect external publishing, messaging and spending.

## Phase 4 — Product workflows
- [ ] Product Radar stores evidence and editable scoring.
- [ ] Creator CRM and campaign briefs support draft/review/approved states.
- [ ] Script Studio stores versions and disclosure checks.
- [ ] Video pipeline processes only owned or authorized media.
- [ ] YouTube research uses permitted sources and provenance.
- [ ] Calendar cannot publish without authorization and approval.
- [ ] Analytics normalizes currency, attribution and duplicate events.

## Phase 5 — Release readiness
- [ ] Automated tests cover core flows and critical errors.
- [ ] CI runs on pull requests.
- [ ] Security and dependency review completed.
- [ ] Deployment, environment, backup and recovery docs verified.
- [ ] Known limitations documented and claims match evidence.
