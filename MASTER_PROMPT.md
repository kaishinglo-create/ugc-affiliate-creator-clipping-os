4. JEV DECISION ENGINE

JEV ist als spezialisierte Entscheidungsengine vorgesehen.

Die konkrete Integration darf erst implementiert werden, wenn eine offizielle technische Schnittstelle, ein tatsächlicher Modellzugang und das unterstützte Request-/Response-Format verifiziert wurden.

Implementiere zunächst ein internes Interface für:

Entscheidungsanfragen

Schema-Validierung

Normalisierung der Ergebnisse

Zeitüberschreitungen

kontrollierte Wiederholungen

Fehlerbehandlung

Versionsinformationen

Entscheidungsprotokolle

Kosten- und Latenzerfassung, soweit verfügbar

JEV soll bei geeigneten Aufgaben strukturierte Entscheidungen unterstützen:

Produktpriorisierung

Auswahl von Content-Kandidaten

Kampagnenpriorisierung

Clip-Auswahl

Auswahl nächster Arbeitsschritte

Optimierungsvorschläge

Erkennung fehlender Daten

Eskalation zur menschlichen Freigabe

Erfinde keine JEV-Endpunkte, keine Konfidenzwerte und keine Modellfähigkeiten.

Wenn JEV nicht erreichbar ist, muss das System den Zustand NOT_CONFIGURED, UNAVAILABLE oder einen entsprechend zutreffenden Fehlerstatus anzeigen.

Ein lokaler Mock ist ausschließlich für Tests zulässig und muss eindeutig als Simulation markiert sein.

Eine Funktion ist erst fertig, wenn:

ihre Eingaben validiert werden,

ihr Datenzugriff korrekt funktioniert,

ihre Berechtigungen serverseitig geprüft werden,

Fehler verständlich behandelt werden,

relevante Tests existieren und ausgeführt wurden,

die Ergebnisse dokumentiert sind.

Ein leeres UI, ein statischer Mock oder eine bloße TODO-Markierung erfüllt diese Kriterien nicht.

Nicht erreichbare externe APIs müssen als externe Blockade dokumentiert werden. Du darfst die Plattform intern weiterentwickeln, solange dies sicher möglich ist.

11. DEFINITION OF DONE

Das Projekt ist erst COMPLETE, wenn:

alle Pflichtmodule implementiert oder ihre echten externen Blockaden präzise dokumentiert sind,

alle definierten kritischen Kernprozesse funktionieren,

Berechtigungs- und Workspace-Isolationstests bestanden wurden,

Typecheck und Lint erfolgreich sind, sofern im Projekt vorhanden,

die relevanten Tests erfolgreich sind,

der Produktionsbuild erfolgreich ist,

keine bekannten kritischen Sicherheitsprobleme offen sind,

keine erfundenen Integrationen als verbunden dargestellt werden,

alle erforderlichen Dokumentationen aktuell sind,

die Abschlussprüfung anhand der tatsächlichen Ergebnisse durchgeführt wurde.

Unterscheide zwischen internem Projektabschluss und extern blockierten Integrationen. Behaupte nicht, dass eine nicht erreichbare JEV- oder Social-Media-API produktiv funktioniert.
